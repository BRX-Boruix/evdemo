# evdemo

BORUIX 的**端到端验收程序**：验证键盘事件流能被用户态消费，并产出正确的字节。

[English](README.en.md)

## 数据链

```
键盘中断 → 事件节点（16 字节记录）→ 转换层（键位映射、修饰键）→ 本程序逐条消费回显
```

## 测什么

1. **事件记录可被用户态读取**——程序经真实系统调用打开事件节点并读取记录；
2. **记录能正确解析**——每条 16 字节的记录被解析为按键事件；
3. **产出的字节正确**——经键位映射与修饰键处理后，输出的字符与按下的键一致；
4. **空读会在内核阻塞，而非返回"文件结束"或忙等**——事件环为空时，读取操作在当前进程内挂起，
   按键到达时被唤醒。**用户态不做自旋**。

## 诊断形态

本程序**刻意绕开**了常规的事件源组件，直接走"打开 → 读取 → 解析"这条路径，并把每轮读取的真实
结果（字节数与错误码）打印出来。这样做是为了在排查「积压吐完后读取无产出」这类问题时**拿到直接
证据**——常规组件会把中间细节隐藏掉。

行为与常规组件等价（同一条链）。组件路径本身的验收见 [`evsrcdemo`](https://github.com/BRX-Boruix/evsrcdemo)。

## 诚实边界

本程序证明「事件流可被用户态消费、产出正确字节，且空读会在内核阻塞」。

它**不**证明 `shell` 已经切换到这个输入源——组件的接线是另一回事。

```

├── linker.ld     # 用户态段布局
└── src/
    └── main.rs   # 事件读取、解析与回显
```
